# Implementation Plan: Skeleton to shadcn-svelte Migration

**Branch**: `012-shadcn-migration` | **Date**: 2026-02-04 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/012-shadcn-migration/spec.md`

## Summary

Migrate the Rusty Shed frontend from Skeleton UI (v4.9.0) to shadcn-svelte (v1.1.1) while preserving the Steampunk custom theme system and ensuring 100% visual and functional parity. The migration includes standardizing page header layouts, removing Dashboard labels, and ensuring error toast notifications maintain consistent positioning and behavior in the top-right corner.

## Technical Context

**Language/Version**: Svelte 5.49.1 + SvelteKit 2.50.1 (frontend), Tauri 2.9.x (desktop)  
**Primary Dependencies**:

- UI Library: shadcn-svelte 1.1.1 (replacing @skeletonlabs/skeleton 4.9.0)
- Styling: Tailwind CSS 4.1.18 + custom Steampunk themes
- Component Primitives: bits-ui (shadcn-svelte uses this foundation)
- Icons: lucide-svelte 0.562.0 (compatible with both libraries)
- Forms: @tailwindcss/forms 0.5.11

**Storage**: N/A (frontend only, data managed by Tauri backend)  
**Testing**: vitest with happy-dom + @testing-library/svelte (existing test infrastructure)  
**Target Platform**: Desktop application (Windows, macOS, Linux) via Tauri 2; responsive web design (mobile to desktop)
**Project Type**: SvelteKit web frontend + Tauri desktop wrapper
**Performance Goals**: No degradation from baseline; maintain <10% performance impact (SC-006)  
**Constraints**:

- Must preserve Steampunk theme system (custom colors, fonts, variants)
- All interactive components must behave identically to Skeleton versions
- Dark mode / light mode switching must work without interruption
- Toast notifications must render in top-right corner with identical UX
- Custom component extensions must be migrated or replaced

**Scale/Scope**:

- Estimated component count: 30-50 UI components (buttons, forms, modals, tables, dropdowns, etc.)
- Codebase size: ~200 .svelte files + ~500 .ts files in src/
- Breaking changes: None (internal library swap only)

## Phase 0: Outline & Research

### Key Research Areas

1. **shadcn-svelte Component Coverage** - Identify mapping between current Skeleton components and shadcn-svelte equivalents
   - Button, Card, Input, Form, Modal, Dropdown, Tabs, Tables, etc.
   - Missing equivalents strategy (custom wrapper or alternative)

2. **Steampunk Theme Integration** - Validate custom theme system works with shadcn-svelte
   - CSS variable scope and Tailwind token integration
   - Dark/light mode switching mechanism

3. **Toast/Notification System** - Verify top-right positioning with shadcn-svelte notification component
   - Stacking behavior and auto-dismiss timing
   - Styling preservation

4. **Page Header Standardization** - Define exact layout structure for "My Collection" template
   - Font sizes, spacing, typography hierarchy
   - Apply to all pages consistently

5. **Breaking Change Risk** - Identify if any custom extensions exist that shadcn-svelte doesn't support
   - LayerChart SVG compatibility
   - FormKit or custom form components
