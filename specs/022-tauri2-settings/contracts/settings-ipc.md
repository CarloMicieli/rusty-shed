# IPC Contracts: Settings Commands

**Feature**: Migrate Tauri 2 Settings
**Date**: 2026-02-15
**Transport**: Tauri IPC (invoke)
**Type Generation**: specta → TypeScript

---

## Overview

This document defines the IPC commands for settings management. All commands follow the Tauri `invoke` pattern with specta-generated TypeScript types.

**Conventions** (per ADR 8 and Constitution):

- **Args**: Transport DTOs for write operations (derive `Debug, Clone, Validate, Type, Deserialize`)
- **Input**: Internal use-case inputs (domain types)
- **Result**: Response types (derive `Debug, Clone, Type, Serialize`)
- **Error**: String error messages (or structured error type if needed)

---

## Command: `initialize_settings`

**Purpose**: Initialize settings on first application run with OS locale detection

**When to call**: On application startup, before main window is shown

**Use case**: First-run experience (FR-007, FR-008)

### Request

**Arguments**: None

**Rust Signature**:

```rust
#[tauri::command]
#[specta::specta]
pub async fn initialize_settings(
    app: AppHandle
) -> Result<UserSettings, String>
```

### Response

**Success** (`200 OK` equivalent):

```typescript
{
  currency: string; // e.g., "EUR"
  language: 'en' | 'it'; // Detected from OS or fallback
  measure_unit: 'Metric' | 'Imperial';
  favourite_scale: string; // Empty string by default
  power_system: 'DC' | 'AC' | 'DCC';
  first_run: boolean; // true on first call, false thereafter
}
```

**Error** (`4xx/5xx` equivalent):

```typescript
string; // Error message, e.g., "Failed to detect OS locale"
```

### Behavior

1. Check if settings already exist in store
2. If exists → Return existing settings (idempotent)
3. If not exists:
   - Call `tauri_plugin_os::locale()` to detect OS language
   - Parse locale code (e.g., "it-IT" → "it")
   - Set `language` to detected language if supported, else "en"
   - Set all other fields to defaults
   - Set `first_run` to `true`
   - Save settings to store
   - Return initialized settings

**State Transition**: `[No settings]` → `[Settings with first_run=true]`

### Example Usage (TypeScript)

```typescript
import { invoke } from '@tauri-apps/api/core';

const settings = await invoke<UserSettings>('initialize_settings');
console.log(`Initialized with language: ${settings.language}`);
```

## Command: `get_settings`

**Purpose**: Retrieve current user settings

**When to call**: On application startup (after initialize), when loading settings page

**Use case**: Display current settings in UI (FR-002)

### Request

**Arguments**: None

**Rust Signature**:

```rust
#[tauri::command]
#[specta::specta]
pub async fn get_settings(
    app: AppHandle
) -> Result<UserSettings, String>
```

### Response

**Success**:

```typescript
{
  currency: string;
  language: 'en' | 'it';
  measure_unit: 'Metric' | 'Imperial';
  favourite_scale: string;
  power_system: 'DC' | 'AC' | 'DCC';
  first_run: boolean;
}
```

**Error**:

```typescript
string; // e.g., "Settings not initialized"
```

### Behavior

1. Load settings from store (in-memory cache)
2. If not found → Return error (should not happen after `initialize_settings`)
3. Return current settings

**No side effects**: Read-only operation

### Example Usage (TypeScript)

```typescript
const settings = await invoke<UserSettings>('get_settings');
```

## Command: `update_settings`

**Purpose**: Update one or more user settings

**When to call**: When user changes settings in settings page

**Use case**: Persist settings changes (FR-003, FR-004)

### Request

**Arguments**:

```rust
#[derive(Debug, Clone, Validate, Type, Deserialize)]
pub struct UpdateSettingsArgs {
    #[validate(length(min = 1, max = 10))]
    pub currency: Option<String>,

    pub language: Option<Language>,

    pub measure_unit: Option<MeasureUnit>,

    #[validate(length(max = 20))]
    pub favourite_scale: Option<String>,

    pub power_system: Option<PowerSystem>,
}
```

**TypeScript Type** (generated by specta):

```typescript
interface UpdateSettingsArgs {
  currency?: string;
  language?: 'en' | 'it';
  measure_unit?: 'Metric' | 'Imperial';
  favourite_scale?: string;
  power_system?: 'DC' | 'AC' | 'DCC';
}
```

**Rust Signature**:

```rust
#[tauri::command]
#[specta::specta]
pub async fn update_settings(
    app: AppHandle,
    args: UpdateSettingsArgs
) -> Result<UserSettings, String>
```

### Response

**Success**: Returns updated settings

```typescript
{
  currency: string;
  language: 'en' | 'it';
  measure_unit: 'Metric' | 'Imperial';
  favourite_scale: string;
  power_system: 'DC' | 'AC' | 'DCC';
  first_run: boolean;
}
```

**Error**:

```typescript
string; // e.g., "Invalid currency: must be 1-10 characters"
```

### Behavior

1. Validate `args` using `validator::Validate`
2. If validation fails → Return error with details
3. Load current settings from store
4. Merge `args` into current settings (only update provided fields)
5. Validate merged settings (domain validation)
6. If valid → Save to store → Return updated settings
7. If invalid → Return error

**State Transition**: `[Current settings]` → `[Updated settings]`

**Reactivity**: After successful update, frontend should update UI reactively

### Example Usage (TypeScript)

```typescript
// Update only language
const updated = await invoke<UserSettings>('update_settings', {
  args: { language: 'it' }
});

// Update multiple fields
const updated = await invoke<UserSettings>('update_settings', {
  args: {
    currency: 'USD',
    measure_unit: 'Imperial'
  }
});
```

## Command: `reset_settings`

**Purpose**: Reset all settings to defaults (factory reset)

**When to call**: When user clicks "Reset to Defaults" button in settings page (optional feature)

**Use case**: Allow users to recover from misconfiguration

### Request

**Arguments**: None

**Rust Signature**:

```rust
#[tauri::command]
#[specta::specta]
pub async fn reset_settings(
    app: AppHandle
) -> Result<UserSettings, String>
```

### Response

**Success**: Returns default settings

```typescript
{
  currency: 'EUR';
  language: 'en' | 'it'; // Based on current OS locale, or "en"
  measure_unit: 'Metric';
  favourite_scale: '';
  power_system: 'DC';
  first_run: false; // Preserves first_run state
}
```

**Error**:

```typescript
string; // e.g., "Failed to reset settings"
```

### Behavior

1. Create new settings with default values
2. Detect OS locale and set language (same as `initialize_settings`)
3. Set `first_run` to `false` (do NOT reset first-run flag)
4. Save to store (overwriting current settings)
5. Return default settings

**State Transition**: `[Current settings]` → `[Default settings (except first_run)]`

**Note**: This command is **optional** and not required by the spec. Include if desired for UX.

### Example Usage (TypeScript)

```typescript
const defaults = await invoke<UserSettings>('reset_settings');
```

## Command: `mark_first_run_complete` (Internal)

**Purpose**: Mark first run as complete after successful initialization

**When to call**: Internally by `initialize_settings` or after first successful app startup

**Use case**: Prevent re-running first-time setup (FR-012)

### Request

**Arguments**: None

**Rust Signature**:

```rust
#[tauri::command]
#[specta::specta]
pub async fn mark_first_run_complete(
    app: AppHandle
) -> Result<(), String>
```

### Response

**Success**: `void` (Unit type)

**Error**:

```typescript
string; // e.g., "Settings not initialized"
```

### Behavior

1. Load current settings
2. Set `first_run` to `false`
3. Save to store
4. Return success

**State Transition**: `[first_run=true]` → `[first_run=false]`

**Alternative Design**: This functionality could be built into `initialize_settings` instead of being a separate command.

## Error Handling

### Error Types

All commands return `Result<T, String>` where:

- `T`: Success response type
- `String`: Human-readable error message

**Error Categories**:

1. **Validation errors**: "Invalid currency: must be 1-10 characters"
2. **Storage errors**: "Failed to save settings to store: disk full"
3. **Not found errors**: "Settings not initialized"
4. **OS errors**: "Failed to detect OS locale"

### Frontend Error Handling

**Pattern**:

```typescript
try {
  const settings = await invoke<UserSettings>('update_settings', { args });
} catch (error) {
  console.error('Settings update failed:', error);
  // Show error toast to user
  showToast({ type: 'error', message: String(error) });
}
```

**User-facing messages**: Use Paraglide for translating error messages:

```typescript
catch (error) {
  showToast({
    type: 'error',
    message: m.settings_update_failed({ error: String(error) })
  });
}
```

## Migration from Previous Implementation

**If settings currently in SQLite**:

No automatic migration (per spec FR-001). Previous settings are abandoned.

**Recommendation**: Document this breaking change in release notes and provide migration guide for users who want to manually transfer settings.

---

## Security Considerations

**Input validation**: All `Args` types validated at IPC boundary before reaching use cases

**No SQL injection risk**: Using tauri-plugin-store (JSON), not SQL database

**File permissions**: Settings file uses OS-default permissions (user read/write only)

**No sensitive data**: Settings contain no passwords, tokens, or PII
