# Quickstart: Rolling Stock Progressive Editing

**Branch**: `024-rolling-stock-edit` | **Date**: 2026-02-18

This guide helps a developer get oriented and start implementing feature `024-rolling-stock-edit` from scratch.

---

## Feature Overview

Three progressive interaction tiers for enriching rolling stock data:

| Tier                  | Fields                                                    | Interaction                       | Command                                                                                       |
| --------------------- | --------------------------------------------------------- | --------------------------------- | --------------------------------------------------------------------------------------------- |
| In-place text         | Model description, Model details                          | Click → edit → blur/Escape        | `update_railway_model_text`                                                                   |
| Constrained selection | Scale, Era (model) + Railway Company (rolling stock card) | Badge click → picker              | `update_railway_model_classification`, `update_rolling_stock_railway_company`                 |
| Technical drawer      | Full 4-section spec per rolling stock unit                | "Edit Specs" button → side drawer | `update_rolling_stock_specifications` + `update_rolling_stock_identification` (card in-place) |

## Backend: Where to Start

### Step 1 — Add `RollingStockUpdated` to `RailwayModelEvent`

File: `src-tauri/src/catalog/domain/railway_model/railway_model_event.rs`

```rust
RollingStockUpdated {
    event_id: Uuid,
    railway_model_id: RailwayModelId,
    rolling_stock_id: RollingStockId,
    timestamp: NaiveDateTime,
    changed: serde_json::Value,
},
```

### Step 2 — Add new domain methods to `RailwayModel`

File: `src-tauri/src/catalog/domain/railway_model/railway_model.rs`

Existing pattern to follow (already in file):

```rust
pub fn update_description(&mut self, description: String) {
    self.description = description;
    self.push_event(RailwayModelEvent::RailwayModelUpdated {
        event_id: Uuid::new_v4(),
        railway_model_id: self.id.clone(),
        timestamp: Utc::now().naive_utc(),
        changed: serde_json::json!({ "description": self.description }),
    });
}
```

Add similarly for `update_scale`, `update_epoch`, `update_rolling_stock_identification`, `update_rolling_stock_railway_company`, `update_rolling_stock_specifications`.

### Step 3 — Extend the repository `save()` to handle new event

File: `src-tauri/src/catalog/infrastructure/railway_model/sqlite_railway_model_repository.rs`

Find the existing `match event { ... }` block in `save()` and add:

```rust
RailwayModelEvent::RollingStockUpdated { rolling_stock_id, changed, .. } => {
    self.update_rolling_stock_from_patch(&rolling_stock_id, &changed).await?;
}
```

Then implement `update_rolling_stock_from_patch` that builds a SQL UPDATE from the `changed` patch. See `data-model.md` for the full SQL.

### Step 4 — Write use cases (one per command)

Files in `src-tauri/src/catalog/application/`:

- `update_railway_model_text.rs`
- `update_railway_model_classification.rs`
- `update_rolling_stock_identification.rs`
- `update_rolling_stock_railway_company.rs`
- `update_rolling_stock_specifications.rs`

Follow the existing `add_railway_model.rs` use case pattern:

1. Validate input with `ValidationContext`
2. Load aggregate from repository
3. Call domain method
4. Save aggregate (repository drains events)

### Step 5 — Add 5 Tauri command handlers

File: `src-tauri/src/catalog/interface/command_handlers.rs`

Follow the existing `create_railway_model` handler pattern. Each command:

1. `args.validate()?`
2. `let mut uow = state.unit_of_work().await?`
3. `UseCase::execute(&mut uow, args.try_into()?).await?`
4. `uow.commit().await.map_err(CommandError::from)?`

### Step 6 — Register new commands in Tauri builder

File: `src-tauri/src/lib.rs` (or wherever commands are registered)

Add all 5 new command functions to the `generate!()` macro and `invoke_handler!()`.

### Step 7 — Rebuild to regenerate TypeScript bindings

```bash
cargo build --manifest-path src-tauri/Cargo.toml
# bindings.ts is auto-regenerated by tauri-specta
```

## Frontend: Where to Start

### Step 1 — Create `InPlaceEdit.svelte`

Location: `src/lib/components/InPlaceEdit.svelte`

Props interface:

```typescript
interface Props {
  value: string; // Current value (display mode)
  placeholder?: string; // Shown when empty
  multiline?: boolean; // true = textarea, false = input
  onSave: (value: string) => Promise<void>; // Called on blur
}
```

State machine using `$state`:

- `isEditing: boolean` — toggles between display and input
- `editValue: string` — current input value
- `isSaving: boolean` — shows spinner, disables input
- `error: string | null` — error message; keeps isEditing=true

Hover affordance:

```svelte
<div class="group relative cursor-text rounded px-1 hover:bg-muted/40 hover:ring-1 hover:ring-dashed hover:ring-border">
```

### Step 2 — Create `BadgePicker.svelte`

Location: `src/lib/components/BadgePicker.svelte`

Props interface:

```typescript
interface Props {
  value: string; // Currently selected display value
  options: { id: string; label: string }[]; // Available options
  onSelect: (id: string) => Promise<void>; // Called on selection
}
```

Uses a `$state` boolean `isOpen` + click-outside detection. Closes on Escape. Position the dropdown near the triggering element using `position: absolute` anchored to the trigger slot.

### Step 3 — Create `RollingStockSpecsDrawer.svelte`

Location: `src/lib/features/rolling-stock-edit/components/RollingStockSpecsDrawer.svelte`

Props:

```typescript
interface Props {
  open: boolean;
  railwayModelId: string;
  rollingStockId: string;
  onClose: () => void;
}
```

On open:

1. Call `commands.getRailwayModelById(railwayModelId)` to load current values
2. Find the matching rolling stock in the result
3. Populate `$state` form object with all current values
4. Store original values snapshot for dirty-check

Four sections: Identification → Technical → Control → Coupling (see FR-022 to FR-026 in spec.md).

Constrained fields within the drawer:

- **Control Type**: `<select>` or `BadgePicker` with options from `Control` enum: `NoDcc`, `DccReady`, `DccFitted`, `DccSound`
- **DCC Interface**: `<select>` with `DccInterface` enum values

### Step 4 — Update `RollingStockCard.svelte`

Add `InPlaceEdit` for: series_code, road_number, livery, depot
Add `BadgePicker` for: railway_company
Add "Edit Specs" button that opens `RollingStockSpecsDrawer`

### Step 5 — Update Railway Model detail display

In `RailwayModelCard.svelte` or the relevant detail page component:
Add `InPlaceEdit` for: description, details
Add `BadgePicker` for: scale, era

### Step 6 — Add Paraglide i18n messages

For each new message key listed in `research.md §8`, add an entry to the corresponding `messages/*.json` file (or the primary locale file if single-locale). Run `pnpm prepare` to regenerate the compiled message module.
