# Implementation Plan: Collection Item Detail View

**Branch**: `026-collection-item-detail` | **Date**: 2026-02-22 | **Spec**: [spec.md](spec.md)

## Summary

Refactor the collection item route from `/models/[...modelId]` (model-ID-based) to
`/collection/[itemId]` (collection-item-ID-based). Introduce a module-level Svelte 5 singleton
store (`collectionStore`) to cache collection data globally and eliminate redundant IPC calls when
navigating to an item. Add a "Collection Identity & Value" sidebar panel that surfaces acquisition,
condition, operational, and personal context data from the existing `CollectionItemView` payload.
Extend navigation active-state logic with `additionalPrefixes` so the "Collection" nav entry stays
highlighted for all `/collection/*` paths.

No new Tauri backend commands are required. No database migrations are needed.

## Phase 1: Design and Contracts (Complete)

See [data-model.md](data-model.md) and [contracts/ipc-commands.md](contracts/ipc-commands.md).

### Key design points

1. **`CollectionStore` (module singleton)**: Wraps `getCollection()` with a cache gate
   (`items.length > 0`). Exposes `fetch()`, `refresh()`, `getItemById(id)`. The layout's
   startup preload calls `collectionStore.fetch()`; mutations call `refresh()` after write.

2. **Detail page loading flow**:
   - Step 1: `collectionStore.fetch()` (cache-first)
   - Step 2: Find item by `itemId` from store — instant if already loaded
   - Step 3: `Promise.all([getRailwayModelById, getRailwayModelImage, getSellerById?])`
   - Render: model card (left panel) + sidebar (right panel)

3. **`CollectionItemSidebar.svelte`**: New component with four sections. Each section receives
   typed props and handles null gracefully. All strings via Paraglide.

4. **Navigation extension**: `additionalPrefixes?: string[]` added to `NavigationItem`.
   `isActive()` checks primary href + `usePrefixMatch` + new `additionalPrefixes`. Minimal
   blast radius — only the collection nav item is changed in config.

5. **No backend changes**: All required data is already in `CollectionItemView` except seller
   name (resolved via existing `getSellerById`). `OwnedRollingStockView.digital` has
   `dcc_address` and `installed_decoder_id`. Decoder name is parsed from the URN.

## Risk Register

| Risk                                                          | Likelihood       | Mitigation                                                                 |
| ------------------------------------------------------------- | ---------------- | -------------------------------------------------------------------------- |
| `collectionStore` not populated on direct page refresh        | High (by design) | `fetch()` called on mount guards this path; store re-fetches when empty    |
| `PurchasedInfo.seller` is null for legacy items               | Medium           | Acquisition section shows "not recorded" empty state; no crash             |
| Multiple `OwnedRollingStockView` entries per item             | Low              | Operational section maps over array with per-entry display                 |
| Old `/models/` route referenced somewhere not found in search | Low              | Run grep before deleting; inspection confirms single call site             |
| Paraglide message keys needed for sidebar strings             | Certain          | Add keys to `messages/en.json` before implementing the component           |
| Layout scroll on narrow screens                               | Medium           | Sidebar stacks below card via `flex-col lg:flex-row`; best-effort per spec |
