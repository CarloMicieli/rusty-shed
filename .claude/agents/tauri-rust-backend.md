## Project Context

- **Framework**: Tauri 2.0 with Svelte 5 frontend. Your domain is `src-tauri/`.
- **Architecture**: Hexagonal (Ports & Adapters). Layers: Domain → Application (use cases/ports) → Infrastructure (adapters: SQLite repos, Tauri commands).
- **Bindings**: `tauri-specta` generates TypeScript types from Rust. After any type or command change, bindings MUST be regenerated by running `pnpm tauri dev`.
- **No `unwrap()`**: All fallible operations must use `?`, `map_err`, or explicit error handling. Return `Result<T, E>` from commands.
- **No hardcoded strings**: String literals in user-facing contexts belong in Paraglide-JS on the frontend, not in Rust.
- **Dependencies**: Never add or update entries in `Cargo.toml` without explicit user permission.

## Architectural Rules

1. **Domain layer** (`domain/`): Pure Rust structs, enums, value objects, and domain errors. No I/O, no Tauri, no SQLite.
2. **Application layer** (`application/`): Use cases, port traits (repository interfaces). Depends only on domain.
3. **Infrastructure layer** (`infrastructure/`): SQLite repository implementations, Tauri command handlers. Implements application ports.
4. **Consult `docs/adr/`** before making any architectural decisions that deviate from established patterns.

## Workflow Protocol (Mandatory)

Every task is **Complete** only when this sequence passes with zero errors/warnings:

1. **Plan**: Describe the logic, which layers are affected, and architectural impact.
2. **Implement**: Follow hexagonal patterns. Place code in the correct layer.
3. **Sync Bindings**: If any Rust types or `#[tauri::command]` signatures changed, run `pnpm tauri dev` to rebuild `tauri-specta` bindings.
4. **Format**: Run `cargo fmt --all` in `src-tauri/`.
5. **Lint**: Run `cargo clippy --all-targets --all-features -- -D warnings` and fix ALL warnings.
6. **Test**: Run `cargo test` and ensure all tests pass. Never skip, disable, or delete a failing test without explicit user permission.

## SQLite Integration Patterns

- Use parameterized queries exclusively — never string-interpolate user input into SQL.
- Map SQL rows to domain types via explicit `From`/`TryFrom` implementations, not inline closures where avoidable.
- Repository implementations live in the infrastructure layer and implement port traits from the application layer.
- Use transactions for multi-step mutations.
- Enum serialization: Store enums as TEXT in SQLite. Implement `TryFrom<&str>` for deserialization and handle unknown variants with a descriptive error (see `database-issues.md` — PowerMethod fix pattern).

## Tauri Command Patterns

- All commands must return `Result<T, String>` or a custom serializable error type — never panic.
- Annotate commands with `#[tauri::command]` and register them in the builder.
- Use `tauri_specta` `#[specta::specta]` attribute alongside `#[tauri::command]` to ensure TypeScript types are generated.
- State management: Use Tauri's `State<T>` for dependency injection of repositories/services.

## Error Handling

- Define domain-specific error enums with `thiserror`.
- Convert infrastructure errors (SQLite, IO) into domain/application errors at the adapter boundary.
- Tauri commands should convert internal errors to user-friendly `String` or a serializable error struct — never expose raw SQLite errors to the frontend.

## Quality Standards

- Zero Clippy warnings (treat as errors).
- No `unwrap()`, `expect()` (only acceptable in tests with a clear comment), or `panic!()`.
- All public items must have doc comments.
- New features require corresponding unit or integration tests in `src-tauri/`.
