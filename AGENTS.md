# AGENTS — Quick Onboarding for AI Coding Agents

Purpose: concise, actionable guidance for automated agents working in this repo.

1. Big-picture architecture

- Frontend: Svelte 5 runes-only UI (no Svelte stores). Built with Vite.
- Desktop wrapper: Tauri 2.0.
- Backend: Rust-based Hexagonal / Clean Architecture under `src-tauri/` (domain, application/use-cases, infra/adapters).

2. Critical developer workflows (exact commands)

- Install deps (root):
  - `pnpm install`
- Frontend dev server (Vite):
  - `pnpm run dev`
- Tauri + backend dev (rebuilds tauri-specta bindings when needed):
  - `pnpm tauri dev`
- Build (frontend + tauri):
  - `pnpm build`
  - `pnpm tauri build`
- Tests & static checks:
  - `pnpm test` (Vitest)
  - `pnpm run svelte-check`
- Lint & format:
  - `pnpm run lint`
  - `pnpm run format`
- Rust checks (backend):
  - `cd src-tauri && cargo test`
  - `cd src-tauri && cargo clippy --all-targets -- -D warnings`
  - `cd src-tauri && cargo build --release`

3. Project-specific conventions & patterns (concrete examples)

- No hardcoded UI strings: use Paraglide-JS and the `messages/` locale files (`messages/en.json`, `messages/it.json`).
- Never use `.unwrap()` in Rust — prefer explicit `Result` handling and domain error enums (see `docs/RUST_STYLE_MANIFEST.md`).
- Use `tauri-specta` generated TypeScript bindings for Rust types — do NOT re-declare Rust types in TS. Rebuild bindings when Rust APIs/types change by running `pnpm tauri dev`.
- TypeScript: project is strict — avoid `any`. Use `unknown`, generics, or explicit interfaces; use `as const` for literal values.
- Svelte pattern: Runes-only components; avoid stores. Prefer small service/repo modules for IPC with Tauri commands.
- Follow ADRs in `docs/adr/` before making architectural changes.

4. Integration points — where to look

- Tauri commands and registration: search `src-tauri/` for `tauri::Builder` and `invoke_handler`.
- Specta bindings: generated by `tauri-specta` during `pnpm tauri dev` — look for generated JS/TS under `src-tauri/target` or configured frontend bindings path.
- Persistence/DB adapters: inspect `src-tauri/infra` for crates like `rusqlite`, `sqlx`, or migration folders.
- Localization: `messages/en.json`, `messages/it.json` — canonical source for UI strings.
- Docs and ADRs: `docs/adr/` and `docs/RUST_STYLE_MANIFEST.md` for style and architectural rules.

5. Concrete file references (examples to read first)

- `docs/adr/` — architectural decisions to follow.
- `src-tauri/` — domain, application, infra (backend source-of-truth).
- `messages/en.json` — example locale used by Paraglide-JS.
- `.github/copilot-instructions.md` and `CLAUDE.md` — project DNA and agent constraints.
- `package.json` and `pnpm-workspace.yaml` — scripts and workspace config (use `pnpm` only).

6. Debugging tips & quick fixes

- Type mismatch after Rust change: run `pnpm tauri dev` to regenerate `tauri-specta` bindings, then restart `pnpm run dev`.
- Rust panics or build failures: `cd src-tauri && cargo test` and `cargo clippy` locally to reveal issues.
- If bindings are stale, clearing target artifacts and re-running `pnpm tauri dev` can help.
- Search `src-tauri/` for `migrations`, `rusqlite`, `sqlx`, or `sea-orm` if DB issues appear.

7. Rules for automated agents (must follow)

- Only use `pnpm` for JavaScript/TypeScript package management and scripts. Never use `npm` or `yarn`.
- Do not change dependency versions in `package.json` or `Cargo.toml` without explicit human approval.
- Do not introduce hardcoded UI strings; route through Paraglide-JS and `messages/`.
- Never add `.unwrap()` in Rust code.
- Keep TypeScript strictly typed; avoid `any`.
- Use Conventional Commits for commits (e.g. `feat:`, `fix:`, `refactor:`).
